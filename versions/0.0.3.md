# 0.0.3

Changes since 0.0.2.

## Fixed

- **`@ConfFolder` created a folder with a random name that changed on every restart.**

  In `Collector.collect(...)` the folder name was taken from the result of `ReflectUtil.findAnnotation(...)`,
  which returns the `Ann_Class` wrapper, not the annotation value. The wrapper was concatenated into the path
  through its default `toString()`, so a class marked with `@ConfFolder("hi")` got a config path like

  ```
  kz.pompei.scheduler.core.ReflectUtil$Ann_Class@3fed2870/Test1_Scheduler.scheduler
  ```

  The identity hash code differs in every JVM run, so after a restart the scheduler looked into a new folder,
  did not find the existing config, and wrote a fresh one with default schedules — all edits made by the user
  in the config file were effectively ignored.

  Now the folder name is taken from the annotation value (`@ConfFolder("hi")` → `hi/Test1_Scheduler.scheduler`),
  so the config path is stable between restarts.

  File: `kz-pompei-scheduler-core/src/kz/pompei/scheduler/core/Collector.java`

## Tests

- Added `CollectorTest` covering the config path built by `Collector`:
  - folder name comes from the `@ConfFolder` value;
  - no folder in the path when the annotation is absent;
  - `@ConfFolder` declared on a parent class is used as well;
  - the path is the same for two independent `Scheduler` instances (restart simulation);
  - a second collect reuses the already written config instead of creating a new one.
- `ConfigTunnelFake` got the method `writtenLocalPaths()` returning all local paths written to the tunnel.

## Test application (`tst-app`)

- `Test1_Scheduler` demonstrates `@ConfFolder` together with `@FromConf` and `@Schedule`.
- `Main` runs the scheduler on a file-based config tunnel (`ConfigTunnelFile`) in `build/tst-app`,
  so the hot config behaviour can be checked manually on real files.
